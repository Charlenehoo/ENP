# 命名空间设计

为支持插件式 + 黑板模式的重构，我将设计一个清晰的命名空间层次，使用 Lua 表模拟模块。该结构将现有功能整合，并为新架构提供基础。

## 顶层命名空间：`ENP`

所有模组代码均位于 `ENP` 全局表下，避免污染全局命名空间，同时便于其他模组引用。

```lua
ENP = ENP or {}
```

---

## 一级命名空间

| 名称              | 职责       | 说明                                                     |
| ----------------- | ---------- | -------------------------------------------------------- |
| `ENP.Core`        | 核心管理   | 代理注册表、生命周期管理、关系控制                       |
| `ENP.Plugins`     | 插件系统   | 插件定义、注册、执行管道                                 |
| `ENP.Blackboard`  | 黑板工具   | 黑板数据访问辅助函数（可选，实际黑板数据由代理实体持有） |
| `ENP.Config`      | 配置参数   | 所有可调参数（距离、记忆时长、衰减系数等）               |
| `ENP.Utils`       | 工具函数   | 数学、射线、实体等辅助函数                               |
| `ENP.Integration` | 第三方集成 | EDA 状态机、ARC9 武器集成、其他模组适配                  |
| `ENP.Debug`       | 调试工具   | 日志、性能监控、可视化调试                               |

## 二级及更深命名空间

### 1. `ENP.Core`

核心模块，管理代理的创建、销毁、关系以及持久化黑板。

| 子模块                  | 用途                                                                        |
| ----------------------- | --------------------------------------------------------------------------- |
| `ENP.Core.Registry`     | 双向索引表（`_attackersByVictim` / `_victimsByAttacker`），提供增删查改接口 |
| `ENP.Core.Proxy`        | 代理实体类（`enp_proxy`）的初始化、黑板挂载、属性访问                       |
| `ENP.Core.Relationship` | 攻击者与受害者/代理的关系管理（动态添加/移除 `AddEntityRelationship`）      |
| `ENP.Core.Lifecycle`    | 代理生命周期管理（创建、迁移、移除，与事件钩子联动）                        |

```lua
ENP.Core = {
    Registry = {},
    Proxy = {},
    Relationship = {},
    Lifecycle = {},
}
```

### 2. `ENP.Plugins`

插件系统，包含插件基类、注册、执行管道。

| 子模块                | 用途                                               |
| --------------------- | -------------------------------------------------- |
| `ENP.Plugins.Base`    | 插件基类或接口定义（可选，Lua 中可为函数签名约定） |
| `ENP.Plugins.List`    | 插件顺序列表（数组）                               |
| `ENP.Plugins.Helpers` | 插件间共享的辅助函数（如抖动计算、骨骼循环等）     |

实际插件实现则放在 `ENP.Plugins.Impl` 下：

```lua
ENP.Plugins.Impl = {
    SkeletalPosition = function(bb, currentPos) ... end,
    Perception = function(bb, currentPos) ... end,
    Memory = function(bb, currentPos) ... end,
    Penetration = function(bb, currentPos) ... end,
    TacticalDecision = function(bb, currentPos) ... end,
    Jitter = function(bb, currentPos) ... end,
}
```

执行管道可设计为 `ENP.Plugins.Run(bb, startPos)` 函数，依次调用 `ENP.Plugins.List` 中的插件。

### 3. `ENP.Blackboard`

黑板辅助层。由于黑板数据直接存储在代理实体上（如 `proxy._enp_bb`），此层主要提供便利函数：

| 函数                                                             | 用途                                           |
| ---------------------------------------------------------------- | ---------------------------------------------- |
| `ENP.Blackboard.Get(proxy, attacker, victim)`                    | 获取黑板实例（若不存在则创建）                 |
| `ENP.Blackboard.UpdateInputs(bb, attacker, victim, currentTime)` | 填充每帧变化的输入字段                         |
| `ENP.Blackboard.SyncToProxy(bb, proxy)`                          | 将黑板中需要持久化的字段写回代理（如记忆时间） |

```lua
ENP.Blackboard = {
    Get = function(proxy) return proxy._enp_bb end,
    UpdateInputs = function(bb, ...) ... end,
    SyncToProxy = function(bb, proxy) ... end,
}
```

### 4. `ENP.Config`

所有配置参数集中存放，便于调整和国际化。

```lua
ENP.Config = {
    -- 感知参数
    SIGHT_MEMORY_DURATION = 8,
    SOUND_MEMORY_DURATION = 4,
    HEAR_THRESHOLD = 10,          -- dB
    WALL_ATTENUATION_PER_UNIT = 0.1, -- dB/unit

    -- 战斗范围
    MIN_ENGAGE_RANGE = 50,        -- 过近移除关系
    MAX_ENGAGE_RANGE = 1024,      -- 过远移除关系
    HYSTERESIS_ENTER = 1024,      -- 进入范围阈值
    HYSTERESIS_EXIT = 1200,       -- 退出范围阈值

    -- 代理偏移与抖动
    PROXY_OFFSET = 16,
    MAX_JITTER = 32,
    HORIZONTAL_FACTOR = 1.0,
    VERTICAL_FACTOR = 0.2,

    -- 声音
    WEAPON_SOUND_SPL = 140,
    FOOTSTEP_SPL_MAX = 85,
    FOOTSTEP_SPL_FACTOR = 33,     -- 33 * log10(speed)

    -- 调试
    DEBUG = true,
    DEBUG_PRINT_INTERVAL = 2,
}
```

### 5. `ENP.Utils`

通用工具函数，不依赖模组状态。

```lua
ENP.Utils = {
    Math = {
        Clamp = math.Clamp,
        Remap = function(val, inMin, inMax, outMin, outMax) ... end,
        -- 其他
    },
    Ray = {
        TraceLine = util.TraceLine,
        GetWallThickness = function(start, endpos, filter) ... end,
    },
    Entity = {
        IsValid = IsValid,
        GetBonePositionCyclic = function(ent, cache) ... end,
    },
    Sound = {
        DistanceAttenuation = function(dist) return 20 * math.log10(math.max(dist,1)) end,
        FootstepSPL = function(speed) ... end,
    },
}
```

### 6. `ENP.Integration`

第三方模组集成，将外部依赖抽象为接口，便于替换或禁用。

```lua
ENP.Integration = {
    EDA = {
        GetRagdoll = function(player) return player.ORag end,
        GetFields = function(ragdoll) ... end,
        OnStateChange = function(player, callback) ... end,
    },
    ARC9 = {
        GetPenetration = function(weapon) return weapon:GetProcessedValue("Penetration") end,
        GetMaxLayers = function(weapon) return weapon.MaxPenetrationLayers or 3 end,
        PenTable = ARC9 and ARC9.PenTable or {},
    },
}
```

### 7. `ENP.Debug`

调试工具，仅在开发或开启 DEBUG 时生效。

```lua
ENP.Debug = {
    Log = function(level, ...) ... end,          -- 带等级日志
    DrawProxyPositions = function() ... end,     -- 可视化代理位置
    DumpBlackboard = function(proxy) ... end,    -- 打印黑板内容
    Profiler = { Start = ..., Stop = ... },
}
```

## 文件组织与加载

按照上述命名空间，文件结构可规划为：

```
lua/enp/
    init.lua                 -- 加载所有子模块，设置全局 ENP
    core/
        registry.lua         -- ENP.Core.Registry
        proxy.lua            -- ENP.Core.Proxy
        relationship.lua     -- ENP.Core.Relationship
        lifecycle.lua        -- ENP.Core.Lifecycle
    plugins/
        init.lua             -- ENP.Plugins 初始化和执行管道
        impl/
            skeletal_position.lua
            perception.lua
            memory.lua
            penetration.lua
            tactical_decision.lua
            jitter.lua
    blackboard.lua           -- ENP.Blackboard
    config.lua               -- ENP.Config
    utils.lua                -- ENP.Utils
    integration/
        eda.lua              -- ENP.Integration.EDA
        arc9.lua             -- ENP.Integration.ARC9
    debug.lua                -- ENP.Debug
```

在 `autorun/init.lua` 中，只需 `include` 入口文件 `lua/enp/init.lua`，该文件再依次加载各模块。

---

## 命名空间优势

- **清晰职责**：每个模块功能单一，易于理解和维护。
- **避免冲突**：全局仅 `ENP` 一个表，内部结构私有。
- **易于扩展**：新插件只需在 `ENP.Plugins.Impl` 添加文件，并插入到 `List`。
- **配置集中**：所有参数在 `ENP.Config` 中，便于玩家/管理员调整。
- **调试分离**：调试代码与主逻辑分离，生产环境可关闭。

此命名空间设计为插件式 + 黑板模式提供了稳固的基础，同时也兼容现有代码逐步迁移。
